# Namco System 10 crypto and NAND reads

`libpcsxcore/arcade/namcos10_crypto.cpp` provides a standalone C interface to
MAME's actual stateful System 10 decryption equations and small-page NAND
read behavior. It does not emulate a complete System 10 board or establish
that any game boots. No flash contents or device responses are synthesized.

The port includes 35 passive word permutations and XOR defaults, with 29
active decryption profiles: Mr. Driller 2's MEM(M) type 1, 27 MEM(N)/MEMP3
type 2 profiles, and Point Blank 3/Gunbalina's ROM-table nonlinear type 2.
Per-game GF(2) history masks, nonlinear equations and custom IV tables are
extracted unchanged from MAME `namcos10.cpp`. Crypto state follows
`ns10crypt.cpp`: encrypted/plain history, next-word mask, 8-bit MEM(M)
counter, and nonlinear table cursor.

## API

Include `namcos10_crypto.h` and compile `namcos10_crypto.cpp` as C++11.
`ns10_crypto_create` accepts a profile name, MAME game/clone name, or
`ns10_<profile>` configuration name. `ns10_crypto_profile_info` and
`ns10_crypto_lookup` expose type, known-IV mask and default XOR.

`ns10_crypto_control_write` implements the board control register: bit 15
activates and reinitializes the low-four-bit IV; clearing bit 15 disables
stream decryption. Every active `ns10_crypto_decrypt_word` advances the real
history and mask. Inactive calls return raw input without advancing state.
Failed activation returns an explicit error and leaves existing state intact.
`ns10_crypto_get_state`/`set_state` support checkpointing; restore requires
using the same profile and nonlinear table. Device reset disables the engine
and clears histories/counters; reactivation preserves the table cursor,
matching upstream.

The optional nonlinear table remains caller-owned. Point Blank 3/Gunbalina
activation requires its actual ROM table; a missing table returns
`NS10_MISSING_TABLE`. Unknown IV entries in upstream Mr. Driller 2 and
Seishun Quiz return `NS10_UNKNOWN_IV` rather than use MAME's `UNKNOWN=16`
placeholder as an invented key. The active decrypters for `ballpom`,
`gegemdb`, `kd2001`, `slotouji`, `ippo` and `ippo2` are absent upstream;
these profiles retain passive transforms but reject active encryption.

`ns10_crypto_memm_bank_word` preserves the MEM(M) bank pipeline: direct NOR
flash access bypasses crypto; active banked reads decrypt; inactive flash
banks below 0x10 unscramble; inactive data banks bypass. The initial MEM(M)
BIOS copy must use passive unscrambling as the upstream driver does.

`ns10_nand_create` accepts real dump bytes including each 512-byte data page
and 16-byte OOB area, page count, device ID and sequential-row capability.
It supports read commands 00/01/50, address cycles, data bytes/words, ID 90,
status 70 and reset FF. Word reads consume the high byte first. The supplied
dump must exactly match geometry. `ns10_crypto_nand_read_word` applies active
crypto or passive XOR/permutation; NAND0 blocks 0 and 1 bypass only the
passive transform, matching MAME's redirect-table/EEPROM treatment.
The caller supplies the board's latched 24-bit column/row/page address.

MEM/IO's writable XOR register is supported through
`ns10_crypto_dataxor_write`, including its byte swap. Caller code controls
bank selection, command registers and game-specific board behavior.

## Validation and limits

Run `make -f tests/Makefile.namcos10-crypto test`. Tests use 441 fixed streams
covering every known IV across all active profiles, generated by a separate
Python implementation of the MAME equations. Fixtures record the upstream
source SHA256. Tests also cover MEM(M) counter wrap, all 35 passive vectors,
reset/checkpoint/deactivation, table bit order/wrap/reactivation, MEM(M)
banking, NAND command/address/OOB/page boundaries, ID/status, sequential rows
and MEM(N) crypto/bypass rules. The complete suite passes ASan/UBSan.

The small-page NAND API defaults to read-only media. Optional writable backing
enables 32-page block erase and buffered 528-byte page programming, including
OOB, confirm, bit-clearing and reset persistence, following MAME. Bounds and
read-only rejection tests pass under ASan/UBSan. Busy latencies, ECC correction,
large-page devices and bad-block remapping policies remain outside this module.
Intel NOR commands and complete base-board maps belong to the separate board
adapter. Unsupported NAND commands return an error and increment a
state diagnostic. ROM authenticity and nonlinear-table authenticity remain
the ROM loader's responsibility. Three real sets now have
[short native Mac gameplay validation](system10-mac.md).

To update profiles and regenerate independent expected vectors:

```
python3 libpcsxcore/arcade/namcos10_crypto_generate.py /path/to/mame/src/mame/namco/namcos10.cpp
python3 tests/test_namcos10_crypto_vectors_generate.py /path/to/mame/src/mame/namco/namcos10.cpp
```
