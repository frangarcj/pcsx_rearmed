# Simpsons Bowling / GV flash and trackball on Mac

The original `simpbowl` BIOS, EEPROM and CD now execute through the native GV
adapter with the source four-flash daughterboard and UPD4701A trackball. A
8900-frame GL/NEON replay reaches Homer in the bowling lane, Frame 1, SET CURVE,
with the direction arrow and pin map. It consumes 450/450 events, reads the
installed flash, has nonzero sound and reports no board or peripheral faults.
A further 10260-frame replay completes the approach/roll input sequence and
shows fallen pins in both GL and NEON. This is bounded player bowling coverage;
a numerical score table and complete rounds are not claimed.

## Source and media

Source is MAME `deb2f54fe7300e7a192690318beb860159bfd52a`,
`src/mame/konami/konamigv.cpp`, `simpbowl_state`, plus `upd4701.cpp/.h` and the
Fujitsu MBM29F016A profile in `intelfsh.cpp`. The main CPU is CXD8530BQ, 2 MiB
RAM; source CXD8514Q uses type-2 packets and 1 MiB VRAM. NCR53CF96 is 16 MHz,
initiator 7, XM-5401 target 4, with IRQ10/DRQ-gated DMA5.

The shared `999a01.7e` BIOS is 512 KiB, source CRC `ad498d2d` and SHA1
`02a82a2fe1fba0404517c3602324bfa64e23e478`. Original `simpbowl.25c` is 128 bytes,
CRC `2c61050c`, SHA1 `16ae7f81cbe841c429c5c7326cf83e87db1782bf`. Its 173-byte
split ZIP came from the public MAME209RomsOnlyMerged archive; ZIP SHA1 is
`3a25f970ee14275b9bda1409acf6c59404a3f5e1`.

The current original CD came from `arcade_simpbowl/829uaa02.chd`, verified
against archive-file SHA1 `2597ff8d598c825a752053c35212aa8129c6c23b`, size
27232262 bytes. Full `chdman verify` passes. Its source header SHA1 is
`2ec4cc608d5582e478ee047b60ccee67b52f060c`, data SHA1
`f2fd6cb2e4bf65866ceeded02703cb229abea642`. It has one MODE2_RAW track,
24540 units of 2448 bytes, logical size 60073920 bytes, 19584-byte hunks.
An older public CHD had source SHA1 `72b32a863e6891ad3bfc1fdfe9cb90a2bd334d71`
and was rejected; its hash or sectors were not modified to match this profile.

## Source installation and persistence

Missing flash state starts as four erased 2 MiB x8 chips, exactly as the source
constructor does. The first boot shows 25C OK and the four flash ROMs BAD / SEE
MANUAL, matching independent MAME. A test-button boot executes the original
installation program. The replay holds `test` from frame 0 to 2400; after
7200 frames the source firmware shows EEPROM CHECK OK / FLASH-ROM CHECK OK and
EEPROM INITIALIZED / FLASH-ROM INITIALIZED. It performed 16777244 flash command
writes and 8389092 reads. No installation image, return value or CRC is faked.

The 8 MiB payload generated by native execution is byte-identical, chip by chip,
to an independent original-media MAME installation:

| Chip | Image SHA1 |
| --- | --- |
| 0 | `d783b77e5af49a7ce7b298aabba9e291014c1800` |
| 1 | `f4aaebcf06d8d6bfbf0fa3d8007fb72d4edde5a2` |
| 2 | `a78f8afd1515161807b6eb5acf747ee29d5857bf` |
| 3 | `53924e5153db1550bbe076aea99ff1fc91de62a5` |

Combined payload SHA1 is `9cbc1b83dc735e915f200a381bfb84811e852b11`.
Native installation EEPROM also matches MAME exactly, SHA1
`bf6447cb16bf40151d2ea4711ac1d96b125d1174`.

`REGION-DIR/flash.nvram` stores the mutable chips separately from original
media. Its 64-byte header binds the state to the original BIOS/EEPROM/CD profile
and hashes the entire payload. Exact size, magic, version, profile and payload
are checked before activation. Invalid existing state is rejected and retained.
Save writes a process-specific temporary file and renames it after a complete
write. `--nvram FILE` remains the separate 128-byte EEPROM image. Soft reset
retains daughterboard counters, address latch and flash state, matching the
source machine reset, rather than recreating erased devices.

## Registers, controls and sound

Flash reads/writes use the source 16-bit delegate at `1f680080–1f68008f`.
Address registers preserve the three source shift/mask operations. Reading
word offset 4 sets the odd address bit; reading offset 0 increments the address
once per delegate, including byte reads. Programming does not increment it.
The two pairs of x8 chips retain independent command/erase state and IDs
`04/ad`. Programming a zero byte back to one matches MAME's byte-assignment
model, independently checked in its actual CPU address space.

UPD4701A reads occupy the source odd lanes at `1f6800c0–1f6800c7`; the read at
`1f6800c9` pulses both reset inputs. The encoder preserves source chip-select
latching, counter wrap, reset levels, switches and flags. Raw 12-bit ports are
sampled once per core frame, rather than on every register read. Initial X is
FFF because the source trackball X port is reversed.

CSV axes are `p1trackx` and `p1tracky`, absolute raw port counts 0–4095.
Interactive Mac uses fractional relative mouse motion with the source X reversal,
left/right click for buttons 1/2, A/S/D for buttons, 5/6 for coin, 1–4 for start,
and gamepad stick motion accumulated once per frame. Focus loss releases held
buttons. The original operator manual describes selection, position/curve locks,
then the timed Normal or motion-driven Easy bowling approach.

GV source SPU routing swaps channels and applies gain 0.75 at 44100 Hz.
The real SDL capture from the 8900-frame replay contains 6557764 stereo frames;
every sample matches its raw source WAV after that swap and integer gain.
Peak is 2720, audio error is zero. GL/NEON final 2 MiB RAM dumps match; their
raw WAVs are not claimed bit-identical. The CD has no audio track, so this does
not validate the still-pending common-GV CDDA mix.

The explicit `--system-gv-simpbowl-fixture` executes generated MIPS accesses to
four flash chips, autoselect, program, frame-sampled trackball and reset, then
proves image persistence across a process restart. Corrupt/truncated/profile-
mismatched state is rejected without overwriting it. This path is distinct from
authenticated game loading and uses a separate fixture state identity.
Component tests cover width/delegate side effects, timed erase, switch and
counter behavior under O2 and ASan/UBSan. Production SDL tests cover reversed
fractional motion, gamepad sampling, button release and exact swapped stereo.
Adjacent GV/GQ fixtures pass; original Hyper Athlete still enters its running
trial with 110/110 events, 553 DMA requests and zero faults after the source
bus-lane correction. No-board/no-CHD builds explicitly reject this configuration.

Evidence is in `artifacts/boards-mac-20261014`, including
`simpbowl-validation.json`, snapshots, input CSVs, audit and source probe logs.

## Actual bowl in GL and NEON

The 10260-frame replay consumes 598/598 events. It locks position and curve,
starts the approach, rolls the trackball, and ends with multiple pins down in
the actual lane. Both renderers show the same pin-fall camera view, not an
attract-only result. Source time is 171.496811283 seconds; PC is `800635f4`.
Both runs have 67 DMA requests, no pending DMA payload and zero board/peripheral
faults. Their exact 2 MiB RAM dumps match, SHA256
`948e98026fe315e72fd85d78d0ee4e7ba08015561d3506ba8981abc87d66d2a8`.

The two headless raw SPU WAVs also match exactly: 7560268 stereo frames,
44100 Hz, peak 3822, SHA256
`e1f2ed9c8dac177a1e50da2753144508e428371de346c5b67c69f6e4981660a9`.
The separate interactive 8900-frame route check above remains the evidence for
source gain/channel order at SDL. Its raw WAV differs from headless NEON in
46306 of 13115528 samples (maximum absolute difference 355), while its exact
2 MiB game RAM still matches. That SPU batching difference is recorded rather
than treated as full timing/audio fidelity.

The installed flash payload retains the same MAME-matching SHA1 after play,
with zero flash command writes in both player runs. Evidence includes
`simpbowl-bowl-gl.png`, `simpbowl-bowl-neon.png`, their logs and
`simpbowl-player-bowl.csv` in the validation directory. The visible lane number
is not reported as a player score. Full game completion, score-table auditing,
physical trackball calibration and physical Vita remain outside this result.
